# adsched — 直投广告保量排期库

纯内存的 Go 库，由上层投放任务调用，无接口层、无外部依赖。
根据流量预测、直投合同与截至当前边界的实际累计投放，生成剩余时段的
全局最优排期计划：先最小化所有合同最终欠量之和，再最小化总节奏偏差。
即使容量不足，也返回全局最优的欠量计划，而不是拒绝排期。

## 模型约定

- 一天固定 48 个 30 分钟时段，当前时点 `Now` 总在时段边界。
- 每个广告位属于一个发布方并固定一个素材尺寸；合同包含发布方、
  可投放素材尺寸集合、整数保证量 `Q`、起止时段 `[Start, End)`（含起点、不含终点）
  和投放节奏（`Even` 均匀 / `FrontLoaded` 前置）。
- 计划约束：发布方与尺寸必须匹配，时段必须在合同范围内；
  每个广告位每个时段的总分配不超过预测容量；
  每份合同实际累计量加未来分配不超过 `Q`。
- 节奏目标始终使用合同原始保证量与原始起止时段（`H = End - Start`）：
  - 均匀：第 `k` 个时段末累计目标 = `Q*k/H` 向下取整；
  - 前置：第 `k` 个时段末累计目标 = `Q*k*(2H-k)/H²` 向下取整。
- 节奏偏差：每份合同尚未结束的履约时段，在各时段末的预计累计投放量
  （实际投放 + 计划截至该时段的分配）与该时点累计目标之差的绝对值之和。
- 支持用更新后的预测容量和实际累计量重新排期；过去的投放不可改写。

## 使用示例

```go
in := adsched.Input{
    Now: 2, // 当前边界：第 2 个时段结束
    Slots: []adsched.Slot{
        {ID: "slot-1", Publisher: "pub-a", Size: "banner"},
    },
    Capacity: map[string][]int64{
        "slot-1": {0, 0, 5, 5 /* ... 长度 48 ... */},
    },
    Contracts: []adsched.Contract{
        {
            ID: "c-1", Publisher: "pub-a", Sizes: []string{"banner"},
            Q: 5, Start: 0, End: 4, Pacing: adsched.Even,
        },
    },
    Delivered: map[string]int64{"c-1": 0},
}
plan := adsched.Schedule(in)
// plan.Alloc["c-1"]["slot-1"][2] == 3, plan.Alloc["c-1"]["slot-1"][3] == 2
```

`Schedule` 返回的 `Plan.Alloc` 结构为：合同 ID -> 广告位 ID -> 时段 -> 整数曝光数，
只包含非零分配。

## 实现原理

排期被建模为最小费用流：

- 源 -> （广告位， 时段） 节点：容量为预测容量；
- （广告位， 时段） -> 合同链节点：仅当发布方与尺寸匹配且时段在合同范围内；
- 合同链边携带截至各时段末的累计未来投放，费用为该时点节奏偏差的
  分段线性函数（斜率 ±1 的两条并联边）；
- 末段出边容量为剩余保证量 `Q - 实际`，费用附加足够大的履约奖励，
  保证"先欠量最小、再节奏偏差最小"的严格字典序。

SSP（Bellman-Ford 初始势 + Dijkstra 增广）求得全局最优整数流，
直接对应整数曝光计划。
